# 业务服务使用说明

本服提供跨机构用药记录的**就诊授权**、**分段读取**、**导入确认**、**更正通知回执**，以及来源端**结算、冲销、归属与资料覆盖日期**的持续投送。

它只呈现来源记录，不判断药物是否适合服用，也不评价处方是否合理。所有人物、证件、账户和业务编号均为合成值；本地身份令牌只用于区分角色，不是生产鉴权凭据。

---

## 1. 启动与准备

```sh
npm ci --ignore-scripts
npm run check:data
npm run service            # 默认监听 127.0.0.1:4400，状态在 .local/service-state.json
npm test                   # 含业务服务与院方联调端的自动化检查
```

环境变量：

| 变量 | 作用 |
| --- | --- |
| `SERVICE_PORT` / `SERVICE_HOST` | 业务服务监听地址，默认 `4400` / `127.0.0.1` |
| `SERVICE_STATE` | 状态文件，默认 `.local/service-state.json` |
| `PEER_URL` | 院方人员、就诊、更正接收端的地址（已配置时**必须**能连上） |
| `PEER_KEY` | 发送给院方联调端的 `x-peer-key`，默认 `local-synthetic-peer` |

未配置 `PEER_URL` 时，人员与就诊事实取自 `data/catalog.json` 的静态目录，便于本地演示；这只适用于合成资料，生产接入必须配置。

所有业务请求都需要本地身份令牌：

```sh
-H 'authorization: Bearer local-patient-a'
```

身份见 `data/actors.json`：

| 令牌 | 角色 | 可做什么 |
| --- | --- | --- |
| `local-patient-a` / `local-patient-b` | 患者 | 查看本人记录、创建/缩小/撤回授权、查看披露范围 |
| `local-doctor-1` / `local-doctor-2` | 医生 | 凭患者授权分段取数、查看自己的送达记录 |
| `local-assistant-1` | 科室助理 | 不能取数（角色限制） |
| `local-hospital-a` / `local-hospital-b` | 医院病案接收 | 导入确认、查看更正通知、按通知编号回执 |
| `local-source-clinic-a` / `local-source-pharmacy-b` | 来源端 | 投送结算、冲销、归属、覆盖日期 |

业务流水号 `requestId` 由 1—100 位字母、数字、下划线、点或连字符组成。同一角色范围内同一流水号重复提交相同内容返回既有结果（`duplicate: true`），内容不同返回 `409 request_id_conflict`。

## 2. 患者端

### 2.1 查看自己的用药记录

```sh
curl -s -H 'authorization: Bearer local-patient-a' http://127.0.0.1:4400/me/records
```

返回三组，互不混同：

- `valid`：仍有未冲销金额的结算；整单部分冲销时仍在此组，行上带 `reversedAmountMinor` 与 `netAmountMinor`。
- `reversed`：所有行都已全额冲销的结算，仅用于追溯。
- `pending`：**归属尚未确认**的资料，停在待核区，只给单摘要，不给药品明细；价格与药品不会提供给医生。

`coverage` 列出各来源的资料覆盖日期（`coverageThrough`）。患者端与医生端都会明确提示：**未覆盖日期不代表没有购药**。

### 2.2 授权医生在一次就诊中查阅

```sh
curl -s -X POST http://127.0.0.1:4400/grants \
  -H 'authorization: Bearer local-patient-a' \
  -H 'content-type: application/json' \
  -d '{
    "requestId": "grant-20261125-1",
    "hospital": "hospital-a",
    "doctor": "doctor-1",
    "visit": "visit-a",
    "range": ["2026-01-01", "2026-12-31"],
    "expiresAt": "2026-11-25T18:00:00Z"
  }'
```

创建时业务服务会向院方人员接口确认医生在岗且属于该医院，并向就诊接口确认就诊开放且属于该患者与医生；不满足则 `403`，不会留下授权。

患者在手术、转诊或就诊结束时可再调整：

```sh
# 缩小购药时间范围（只能缩小，不能扩大）
curl -s -X PATCH http://127.0.0.1:4400/grants/<grantId> \
  -H 'authorization: Bearer local-patient-a' -H 'content-type: application/json' \
  -d '{"requestId":"grant-narrow-1","range":["2026-10-01","2026-11-24"]}'

# 缩短到期时间（不能延长）
curl -s -X PATCH http://127.0.0.1:4400/grants/<grantId> \
  -H 'authorization: Bearer local-patient-a' -H 'content-type: application/json' \
  -d '{"requestId":"grant-narrow-2","expiresAt":"2026-11-25T12:00:00Z"}'

# 立即撤回
curl -s -X POST http://127.0.0.1:4400/grants/<grantId>/revoke \
  -H 'authorization: Bearer local-patient-a' -H 'content-type: application/json' \
  -d '{"requestId":"grant-revoke-1","reason":"就诊结束"}'
```

**授权不会因再次就诊自动延长。** 就诊结束后需针对新的 `visit` 另行创建授权；旧授权保持原有状态。

### 2.3 查看向哪次就诊开放过什么

```sh
curl -s -H 'authorization: Bearer local-patient-a' http://127.0.0.1:4400/me/grants
```

每条授权返回机构、医生、就诊编号、购药时间范围、到期时间、当前状态、历史修订，以及：

- `disclosure.lines` / `disclosure.pages`：实际返回给医生的行数与页数；
- `disclosure.lineRefs`：来源、单据、行号、日期与当时版本（不含药品名称与金额的复述）；
- `import.receipts` / `import.lines`：医院确认已导入的行数。

`disclosed` 不会被后来的撤回、冲销或归属改正改写——它记录的是当时实际发生过的披露。

## 3. 医生端

### 3.1 可用的授权

```sh
curl -s -H 'authorization: Bearer local-doctor-1' http://127.0.0.1:4400/doctor/grants
```

只列出向当前医生、当前医院开放且未撤回、未过期的授权。

### 3.2 分段取回

```sh
curl -s -H 'authorization: Bearer local-doctor-1' \
  'http://127.0.0.1:4400/doctor/records?grantId=<grantId>&pageSize=1'
```

响应包含 `deliveryId`、`page`、`pageCount`、`totalLines`、`complete`、`nextCursor`、实际行 `lines` 与 `coverage`。

继续取下一页：

```sh
curl -s -H 'authorization: Bearer local-doctor-1' \
  'http://127.0.0.1:4400/doctor/records?grantId=<grantId>&cursor=<nextCursor>'
```

返回的每一行带 `source`（来源）、`bill`、`line`、`revision`（当前来源版本）、`coverageThrough`（该来源资料覆盖日期）、`status` 与冲销金额。

**每次取数都会重新确认**：患者授权仍有效、医生在岗、医生所属医院正确、就诊仍开放且属于该患者和该医生。仅持有患者授权不能替代院方人员与就诊确认，离岗医生或已结束的就诊不能继续取数。科室助理因角色限制不能调用。

### 3.3 分页期间的失效

一次分段读取开始后，以下任一变化会使**已开始的这次读取**失效：

- 患者撤回授权，或缩小范围/缩短到期时间；
- 来源更正了该患者相关行的归属；
- 来源对该次读取范围内已返回的结算发生冲销或更正；
- 授权到期。

此时继续翻页返回 `409 visible_scope_changed`（`details.deliveryId` 与 `completedPages` 指明是哪一次读取）。**已返回的页面仍可在 `GET /doctor/deliveries/<deliveryId>` 查到**，但该送达单状态变为 `interrupted`，不会追加新页，也不能把旧页与新页拼成一个声称完整的当前清单。要获得当前清单，必须重新开始读取（不带 `cursor`）。

分页游标一次性使用，不能重放；篡改游标返回 `400 invalid_cursor`。

### 3.4 查看自己的送达记录

```sh
curl -s -H 'authorization: Bearer local-doctor-1' http://127.0.0.1:4400/doctor/deliveries
curl -s -H 'authorization: Bearer local-doctor-1' http://127.0.0.1:4400/doctor/deliveries/<deliveryId>
```

详情保留当时实际返回的每一页与每一行（`pages[].lines`），以及去重后的披露行列表（`disclosed`）。它不随后续冲销或归属改正被改写。

## 4. 医院病案接收端

### 4.1 确认已导入院内病历

医生取完所需页面后，由医院病案接收方携带 `deliveryId` 与**实际收到的来源行版本**确认：

```sh
curl -s -X POST http://127.0.0.1:4400/hospital/receipts \
  -H 'authorization: Bearer local-hospital-a' \
  -H 'content-type: application/json' \
  -d '{
    "requestId": "import-20261125-1",
    "deliveryId": "<deliveryId>",
    "lines": [
      {"source":"clinic-a","bill":"bill-8","line":"1","revision":1},
      {"source":"clinic-a","bill":"bill-8","line":"2","revision":2}
    ]
  }'
```

规则：

- 只能确认**该送达单实际返回过**的行，否则 `409 line_not_disclosed`；
- `revision` 必须是当时返回的版本，否则 `409 line_revision_mismatch`；
- 只能为本院接收的送达单确认，别家医院调用返回 `403 hospital_mismatch`；
- 同一送达单重复确认相同行返回既有回执（`duplicate: true`），不同行返回 `409 delivery_already_received`。

**接收确认不代表仍有查询权限。** 即使患者已经撤回授权、读取已经被中断，医院仍可完成那次已经开始接收的确认，用于说明实际导入过什么；确认本身不会恢复查询权限，也不会产生新的取数。

```sh
curl -s -H 'authorization: Bearer local-hospital-a' http://127.0.0.1:4400/hospital/receipts
```

### 4.2 处理更正通知

来源迟到冲销、部分冲销或归属改正到达时，业务服务只向**实际导入过该行**的医院生成通知：

```sh
curl -s -H 'authorization: Bearer local-hospital-a' http://127.0.0.1:4400/hospital/notifications
```

每条通知包含：

- `notificationId`：通知编号；
- `kind`：`reversal`（冲销）或 `reattribution`（归属改正）；
- `source` / `bill` / `line`：定位原来源行；
- `importedRevision` 与 `currentRevision`：导入时版本与当前版本；
- `importedReversedAmountMinor` 与 `currentReversedAmountMinor`：冲销金额变化；
- `message`：中文说明；
- `status`：`pending` 或 `acknowledged`；
- `peerDelivery`：是否已登记到院方联调端（配置 `PEER_URL` 时）。

**通知不包含患者身份和药品名称**；未接收过原记录的医院查不到该通知，也不能凭通知编号回执（返回 `404`）。通知按送达单中记录的实际行匹配，即使发送时该患者已不对任何医生开放，迟到冲销也会找到当初接收过行的医院，而不是按当前授权名单另发。

回执：

```sh
curl -s -X POST http://127.0.0.1:4400/hospital/notifications/<notificationId>/ack \
  -H 'authorization: Bearer local-hospital-a' \
  -H 'content-type: application/json' \
  -d '{"requestId":"ack-20261125-1"}'
```

回执幂等：重复回执返回同一 `acknowledgedAt`，不重复推进状态。配置了 `PEER_URL` 时，业务服务还会把通知以稳定请求号投送到院方联调端的 `correction` 操作；联调端只确认 `notificationId` 的 `received`，不透露患者或药品。

## 5. 来源端投送

所有来源端接口只能投送**本机构**的数据（令牌绑定的 `source`）；携带其他 `source` 返回 `403 source_mismatch`。

### 5.1 结算增量

```sh
curl -s -X POST http://127.0.0.1:4400/intake/settlements \
  -H 'authorization: Bearer local-source-clinic-a' \
  -H 'content-type: application/json' \
  -d '{
    "requestId": "clinic-a-bill-8-r1",
    "bill": "bill-8",
    "revision": 1,
    "date": "2026-11-20",
    "localPerson": "p17",
    "lines": [
      {"line":"1","drug":"synthetic-a","amountMinor":2100},
      {"line":"2","drug":"synthetic-b","amountMinor":1800}
    ]
  }'
```

- 结算由 `source + bill + revision` 唯一确定；同一内容重复投送（无论是否更换 `requestId`）不重复计费，返回 `duplicate: true`。
- 两家机构可以使用相同的本地人员号或相同的单据号，服务按 `source` 分别保存，**不合并为一张单据**。
- 新版本必须紧接当前来源版本递增，并携带 `previousRevision`；跳号返回 `409 stale_revision`，缺少原单返回 `409 original_missing`。
- 同一版本不同内容返回 `409 revision_conflict`。

### 5.2 冲销

```sh
curl -s -X POST http://127.0.0.1:4400/intake/reversals \
  -H 'authorization: Bearer local-source-clinic-a' \
  -H 'content-type: application/json' \
  -d '{
    "requestId": "clinic-a-bill-8-r2",
    "bill": "bill-8",
    "revision": 2,
    "originalRevision": 1,
    "reverses": [{"line":"2","amountMinor":600}]
  }'
```

- `reverses` 中的 `amountMinor` 是本修订**实际冲销金额**，不是剩余金额；服务按行累计，累计不得超过原行金额（`409 amount_exceeds_line`）。
- 撤销或更正必须引用原单与来源版本 `originalRevision`；原单版本不存在返回 `409 original_missing`。
- 分次冲销会推进版本；例如先冲 600 后再冲 1200 才能把第 2 行（原 1800）冲净。

### 5.3 归属投送与待核

```sh
# 初次投送，归属尚未确认 -> 进入待核区
curl -s -X POST http://127.0.0.1:4400/intake/bindings \
  -H 'authorization: Bearer local-source-pharmacy-b' \
  -H 'content-type: application/json' \
  -d '{"requestId":"bind-p18-1","localPerson":"p18","person":"person-c","confirmed":false}'

# 核实后确认或改正
curl -s -X POST http://127.0.0.1:4400/intake/bindings \
  -H 'authorization: Bearer local-source-clinic-a' \
  -H 'content-type: application/json' \
  -d '{"requestId":"bind-p17-2","localPerson":"p17","person":"person-b","confirmed":true,"revision":2}'
```

- `confirmed: false` 的资料停在待核区，**不会按姓名相同自动合并**，也不会提供给任何医生；
- 归属版本必须紧接当前版本递增；
- 改正归属后，原患者的新查询立即停止看到错绑记录，正确患者才能收到；
- 已经披露给医生的事实保留在送达记录和披露追溯中，不改写成从未发生；
- 改正会使已导入该行的医院收到 `reattribution` 更正通知。

### 5.4 资料覆盖日期

```sh
curl -s -X POST http://127.0.0.1:4400/intake/coverage \
  -H 'authorization: Bearer local-source-clinic-a' \
  -H 'content-type: application/json' \
  -d '{"requestId":"coverage-20261125","through":"2026-11-25"}'
```

`through` 是本来源已更新至的日期，只能前进不能回退（`409 coverage_regression`）。医生端与患者端都据此提示覆盖范围，避免把尚未更新到的日期当成没有购药。

### 5.5 查看本机构已投送的数据

```sh
curl -s -H 'authorization: Bearer local-source-clinic-a' http://127.0.0.1:4400/source/state
```

`pending` 列出本机构归属尚未确认的结算单摘要（只含来源、单据、日期与本地人员号，不含药品明细）。

## 6. 错误约定

| 状态 | 含义 |
| --- | --- |
| `400` | 字段格式、日期区间、游标或版本参数无效 |
| `401` | 缺少或无效的本地身份令牌 |
| `403` | 角色不允许、医生不在岗/医院不符、就诊关闭/不匹配、授权被撤回或过期 |
| `404` | 授权、送达单、通知不存在，或不属于当前主体 |
| `409` | 请求号冲突、版本跳号、重复确认不同行、分页范围已变化、累计冲销超额 |
| `503` | 院方人员或就诊接口暂时不可用（此时不应视为授权失效，稍后重试） |

错误体统一为 `{ "error": "<代码>", "message": "<中文说明>", "details": { ... } }`。

## 7. 持久性与重启

状态保存为单个 JSON 文件，每次变更整体写入临时文件后原子改名；写失败不改变内存与磁盘状态。停止再启动（或容器重启）后，授权、送达单、导入回执、更正通知、来源投送均可继续办理，未确认的通知不会重复生成。

联调端与业务服务是两个独立进程：业务服务把更正通知投送到联调端的 `correction` 操作（稳定请求号 `correction.<notificationId>`），联调端只确认收到通知编号。两者的状态文件需分别持久化（见 README 的 Docker 说明）。
